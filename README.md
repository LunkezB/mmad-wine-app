# Подбор хороших вин: демо на Streamlit

Приложение к ДЗ-3. Модель (пайплайн StandardScaler + LogisticRegression) по результатам лабораторного анализа оценивает вероятность того, что вино хорошее, то есть получило у экспертов оценку не ниже 7. Модель внутри приложения не обучается, она загружается из `model.joblib`.

## Состав папки

- `app.py` - приложение;
- `model.joblib` - обученный пайплайн;
- `config.json` - порог по умолчанию;
- `test.csv` - тестовая выборка с признаками и столбцом `target`;
- `requirements.txt` - версии библиотек, с которыми приложение запускается.

## Запуск

Нужен Python 3.13 (проверено на 3.13.16). Из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

На Windows виртуальное окружение активируется командой `.venv\Scripts\activate`. Приложение откроется в браузере по адресу http://localhost:8501.

`model.joblib` сохранён в scikit-learn 1.9.1. Если пересохранить модель из ноутбука в другой версии scikit-learn, эту версию нужно указать в `requirements.txt`.

## Вкладки

- Оценка одного вина: ввод 12 признаков, вероятность и решение модели при текущем пороге.
- Модельные метрики: матрица ошибок, precision, recall, F1, ROC- и PR-кривые с точкой текущего порога на тестовой выборке.
- Пакетное предсказание: загрузка CSV, таблица с вероятностью и решением для каждого вина, скачивание результата.
- Что выучила модель: коэффициенты логистической регрессии при стандартизированных признаках.

Порог задаётся ползунком на боковой панели и общий для всех вкладок.

## Кэширование (задание 4.5)

Для модели используется `st.cache_resource`, потому что он хранит один объект на весь сервер и при каждом вызове отдаёт ссылку на него без копирования. Модель мы только читаем (`predict_proba` её не меняет), поэтому одного общего объекта на всех пользователей достаточно. `st.cache_data` при каждом вызове отдаёт новую копию результата, восстановленную из сохранённого pickle. Для таблиц и массивов это правильно: если код в одной сессии изменит DataFrame, кэш и другие пользователи этого не увидят. Для модели такое копирование было бы лишней работой при каждом перезапуске скрипта.

Если вызвать `joblib.load` без декоратора, модель будет заново читаться с диска и восстанавливаться из файла при каждом действии пользователя, например при каждом сдвиге ползунка порога. Приложение станет работать медленнее, хотя модель между перезапусками не меняется.
